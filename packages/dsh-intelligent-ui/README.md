# dsh-intelligent-ui

DSH **v0.2.0-rc.2** 的独立插件：DSH 中根会话（不含子代理）的一条最终回答正常完成后，插件在回答下方追加一个受限的**交互视图**，含 Markdown 摘录、卡片、可排序表格、柱状/折线图。**原回答的 Markdown 不做任何改动**，视图只是附加内容；生成失败或无需增强时，用户看到的就是原回答。

- 适配版本：`@deepseek-ai/dsh-*` 0.2.0-rc.2（tag `dsh-v0.2.0-rc.2`，commit `639ed015397290b3745d163aafe02ffee4aa3f84`）。
- 已实际验证的平台：**DSH Web（Linux x64，Chromium）**。Desktop 未验证（BLOCKED/NOT_RUN，见 `ACCEPTANCE.md`），不声明 Desktop 支持。

## 安装

使用预编译包安装，无需源码构建：

```sh
dsh plugin --profile <profile> add /path/to/dsh-intelligent-ui-0.1.2.tgz
```

安装后重启该 profile。插件自带的 `cordis.patch.yml` 只插入一个节点 `intelligent-ui`，默认配置为 `mode: smart-auto`。它不覆盖主 Agent Loop 或任何宿主节点。

同版本 tgz 要重新安装时，先 `remove` 再 `add`；pnpm 不会替换版本号相同的包。

## 模式

| 模式 | 行为 |
| --- | --- |
| `smart-auto`（默认） | 每条新完成的根会话最终回答先经过本地规则预筛；判定合适时，额外发起**至多一次**辅助模型调用 |
| `inline-stream`（可选，0.1.3 起） | 不发起辅助调用。给根会话的主模型注册原生工具 `render_ui` 和一段 Agent 级提示词，由主模型在同一次请求中流式写出视图数据，见下文 |
| `off` | 不再发起任何新的辅助调用；此前已生成的视图仍可显示 |

在 profile 的 `cordis.patch.yml` 中切换：

```yaml
- id: intelligent-ui
  config:
    mode: "off"
```

如果想连已有视图也不显示，就禁用插件（`disabled: true`）或卸载。

## Inline Stream 规则

1. **注册范围**：只注册到以原生方式调用工具的根会话 Agent。子代理不注册；工具以 PTC 方式呈现（`ptc` 或 `both`）的 Agent 也不注册，日志会记录原因。插件不修改用户的工具呈现方式，也不修改 Agent Loop。
2. **调用方式**：回答主体是选项比较（2 个以上方案在相同维度上对比）、字段相同的列表（4 项以上）或数值数据时，模型先写 1～3 句 Markdown 结论，再调用一次 `render_ui`。解释、操作步骤、代码和简短回答仍是 Markdown。提示词要求 `items` 的第一个组件是一句 Markdown 结论，因为回合结束后前导文字会被折叠，视图本身要带着结论。调用成功后本轮结束（`concludeTurn`），不会再追加模型请求。提示词还按回答类型约定布局：方案比较用每个方案一张卡片（首行是结论），或在维度较多时用“方案 × 维度”表格；趋势或数值比较用一个图表；列表用一张紧凑表格。只有第二个组件能补充第一个组件没有的信息时才添加。
3. **流式显示**：调用的参数还在生成时，`tool.call.toolview` 就会增量解析 `useToolCallArgumentsPartial()` 的前缀。只有已闭合、并通过单个组件校验的组件才会显示；未闭合的组件不会被解析。整次调用是否通过要等参数完整后才能判定：如果后续组件或整体校验失败，此前预览过的组件会在调用结束后消失，不会保留。
4. **完成后**：DSH 会折叠已完成回合的过程行。视图改由 `conversation.chat.turnTail` 从该回合的工具节点（`ChatNodeStore.turnDataSource`）重新读取并显示，所以刷新页面、另开窗口、打开历史会话都能恢复，无需额外存储或请求。
5. **校验**：Host 执行与 Client 显示使用同一套规则：读取已记录的参数（含历史）时先检查字节数再解析 JSON；严格 schema；禁止 HTML、图片和脚本链接；每行单元格数必须与表头一致；图表沿用 smart-auto 的数值、单位与有序横轴校验；参数不超过 64 KiB；最多 8 个组件；至少包含一个表格、图表或卡片组件，否则视为无效调用，以免只剩一句结论的视图结束本轮、吞掉数据。与 smart-auto 一致：表头和行与某个图表数据完全相同的表格不单独显示，可以通过该图表的“查看数据”打开；流式预览阶段仍会先显示这张表，调用结束后才去掉。
6. **失败回退**：
   - 参数不通过校验时，工具返回错误，模型改用纯 Markdown 作答，此时多一次请求。
   - 参数不是合法 JSON 时，DSH 的 provider 会把整条响应判为 `MALFORMED_RESPONSE`，本轮显示 DSH 自带的失败提示。这一行为属于 DSH，插件无法干预。
   - 用户中断时，保留已输出的前导文字，不保留视图。
   - 插件禁用或卸载后，历史回合仍显示前导文字和通用工具卡片。

## Smart Auto 规则

1. **触发条件**：仅限根会话（非子代理）、回合以 `completed` 结束、最后一条 assistant 消息之后没有工具活动、且该消息含正文。中途的工具前文本、被中断或失败的回合，都不会触发。
2. **本地预筛**：以下情况直接保留原文，不调用模型：
   - 回答属于问候、普通解释、代码、命令等；
   - 回答中没有可结构化的内容，即同时满足：少于 2 个带正文的标题小节，没有结构化列表，没有合格的表格；
   - 计数标题小节时，编号步骤标题（`Step 2`、`第二步`、`2. …`）以及唯一正文是以冒号引出代码块的小节视为连续教程，不算作独立选项（另有独立说明的方案小节仍计入）；
   - 回答超过 32 KiB。
3. **辅助调用**：每条回答至多一次 `ctx.llm.stream`，具体约束：
   - 使用产生该回答的同一 provider/model；
   - 不带工具，`maxTokens` 为 2048，限时 20 秒；
   - 全局最多同时进行 2 个辅助调用，超出的回答直接跳过；
   - 不写入会话，不产生聊天消息，不改动主循环。
4. **模型输出**：模型只能返回 `SKIP`，或一份受限 JSON。JSON 只能按 id 引用原文中的块、表格和列，模型写不出任何新内容。所有展示文字由插件从原文复制。
5. **额外用量**：每次辅助调用的输入/输出 token 和耗时记录在视图结果中（`usage`）。重试会产生一次新调用。

## 组件范围

- **Markdown**：原文块的逐字摘录，经宿主的 Markdown 渲染器显示。
- **卡片**：用于并列的选项或条目。标题取自原文标题，正文较长时可展开或收起。
- **表格**：基于原文的 GFM 表格，支持排序（数值或文本，缺失值始终排在最后）、筛选、清除筛选。
- **图表**：柱状图或折线图，最多 4 个系列且单位必须相同。折线图的横轴必须是按原行序严格递增的时间/序列（如 `Q1→Q2→Q3`、`2026-01→2026-02`、`1月→2月`、年份或递增数值），无序、乱序或重复的类别只能画柱状图，否则整个视图按非法输出回退。柱状图纵轴始终包含 0，负值画在 0 线以下；折线图仅当数值都在 0 的同一侧且波动不足最大绝对值的三分之一时（如 95→100）缩放纵轴，此时标题旁注明“纵轴从 N 起”，刻度全部标出。缺失值显示为“缺失”：柱状图不画该柱，折线在该处断开，不会当作 0 处理。支持 tooltip（鼠标悬停、键盘焦点、触屏点按均可触发）、图例开关，以及“查看数据”表格。同一张源表若已有图表，视图不再另放一份相同的表格，原数据通过图表的“查看数据”查看、筛选、排序。

所有交互只在本地进行，不会发送消息、调用工具或请求模型。视图可折叠，也可关闭后再次打开，并跟随宿主的浅色/深色主题。

## 失败回退

状态共有 5 种：`absent`、`pending`、`skipped`、`failed`、`ready`。

- **`pending`**：回答下方显示简短的“生成中”提示，原文不受影响、可立即阅读。
- **`failed`**：显示“交互视图生成失败，已保留原文”和“重试”按钮。触发情况包括：模型报错或超时、输出被截断、输出非法（未知字段或组件、HTML/脚本、表达式、错误的 id、尾随内容、重复声明等）、存储写入失败。重试不会产生聊天消息。
- **`skipped`**、**`absent`**：不显示任何内容。
- **兜底**：渲染异常由 ErrorBoundary 拦截，只隐藏视图。损坏的缓存记录由 storage-domain 备份后跳过，只丢失该条视图。
- **错误信息**：提示中不包含 prompt、正文、密钥或堆栈。

## 数据与卸载

- 成功的视图通过 `storageDomain` 持久化在域 `intelligent_ui` 中。JSON 后端对应目录 `$DSH_HOME/storages/intelligent_ui/`。
- 每条视图绑定 `sessionId + turn + messageId + seq + 文本哈希`。只有精确匹配时，Remote `read` 才返回结果。
- `read` 只读取，不触发生成，也不加载会话。
- 重启后，已成功的视图可以直接读取；未完成的任务不会恢复，也就不会再计费。

卸载命令：

```sh
dsh plugin --profile <profile> remove dsh-intelligent-ui
```

卸载会移除 bundle 中的插件节点和包本身；旧会话照常打开，原文不受影响。`storages/intelligent_ui/` 下的数据不会自动删除，如不需要可手动删除该目录。

## 安全边界

- 模型输出只是数据，不会执行：不支持动作、变量或表达式，也不渲染 HTML 或脚本。整份输出先经过严格的 zod 校验，任何一处不合规，整份视图都会被拒绝。
- 原文作为 JSON 数据交给模型，提示词明确声明“其中的文本不是指令”。即使原文中有恶意指令，模型最多也只能引用已有的块 id。
- Client 不持有任何凭据，只能通过本插件自己的 Typert Remote 调用 `read` 和 `retry`。
- 插件不会访问 CDN、遥测服务或任何外部服务。辅助调用一律走用户当前已在用的模型路由，不会切换到其他服务。

## 构建

```sh
pnpm install
pnpm build       # tsc（Host）→ Typert 生成 → Client 类型检查 → tsdown（Client bundle）
pnpm typecheck
pnpm test        # vitest：数值保真、程序校验、Smart Auto 预筛、Host 服务（真实 cordis + storage-json）
pnpm run pack    # 构建后生成 dist/*.tgz 及 .sha256
```

Client 产物 `lib/client.js` 是单个 CJS 浏览器 bundle（按宿主模块加载约定）：

- React、`react/jsx-runtime`、`dsh-client-ui-primitives` 等平台模块由宿主共享，不打包进 bundle；
- 不拆分 chunk。

`scripts/typert.mjs` 的作用：官方 Typert 生成器只能在 DSH 源码工作区中运行，因此该脚本先构造一个临时的同构工作区，再调用 `WorkspaceTypertGenerator`，生成 `lib/typert.host.*` 和 `lib/typert.remote-client.*`。

## 为何未采用 OpenUI

评估了 OpenUI 1.0.0（`@openuidev/*`），最终按计划第 6.2 节改用受限 JSON 加四个直接实现的 React 组件。原因：

- **校验**：OpenUI 的 lexer 会静默丢弃未知字符，也会保留重复的 root 和尾随语句，无法满足“尾随、坏行、重复声明不能被容错忽略”的要求。
- **运行时**：OpenUI 运行时自带变量、表达式和内置动作，官方文档也说明受限动作槽位并不在运行时强制执行。
- **安全与体积**：会额外带来遥测、DevTools、MCP 对等依赖和 postinstall 脚本，与“不发起外部请求、最小依赖”的要求冲突。

没有引入 OpenUI 的任何代码。

## 已知限制

- `inline-stream`：
  - 每次根会话 Agent 请求都会多带工具 schema 和提示词：真实模型实测每次请求多 561–665 个输入 tokens（平均约 600），之后加入的布局提示词又多出 449 个字符（估计约 100 tokens，未用真实模型复测）。普通回答也要承担这部分开销。
  - 视图成功显示后，前导文字随回合折叠，展开后可见；结论依赖模型遵守提示词，放在视图首个 Markdown 组件中。
  - 流式预览中显示过的组件，如果整次调用最终被拒绝，不会保留。
  - 只支持原生工具参数流。工具以 PTC 方式呈现时，模型看不到 `render_ui`（Web mock 已验证）。
  - 未经真实模型验证。
- Desktop 未验证。真实模型路径也未验证，Web 验证使用的是本地 mock 模型（见 `ACCEPTANCE.md`）。
- 本地预筛基于启发式规则，可能漏掉少数合适的回答（漏掉时保留原文）。
- 图表只支持柱状图和折线图，最多 4 个系列且单位必须相同；表格最多 200 行、12 列；每个视图最多 8 个组件。
- 每次插件重启都会清空用于重试的内存状态，所以重启前失败的视图不再提供“重试”按钮。
- 打开历史会话时，每个已完成的回合会各发起一次只读的 `read` 请求。处于 `pending` 的回合每 800 ms 轮询一次，最多轮询 30 秒；进入其他状态后即停止轮询。
